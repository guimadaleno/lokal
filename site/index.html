lokal

A terminal assistant that runs on a model on your own machine. It runs commands, reads your files and changes them, and asks before anything changes.

curl -fsSLo lokal https://download.guimadaleno.com/lokal/0.2.0/lokal && chmod +x lokal && ./lokal --install

Version 0.2.0, for Linux and WSL on x86-64. One file, which installs itself in ~/.local/bin and keeps itself up to date. Its SHA-256 is in SHA256SUMS.

Your model, your machine

LM Studio, or any server that speaks the OpenAI API. Lokal finds it on its own, from WSL too.

Asks before it acts

Read-only commands run at once. Anything else waits for your yes, and every file change shows its diff first.

Quiet

Its reasoning shows in a small window that clears itself, so only the answer stays. Beside the breathing dot: what it's doing, and for how long.

Set up LM Studio

About five minutes, once.

  1. Install LM StudioFrom lmstudio.ai, on the machine that will run the model.
  2. Download a model that can use toolsLM Studio marks the models that support tool use; Lokal needs one to run commands and edit files.
  3. Load it with room to workA context length of 32k tokens or more: command output and files fill it up.
  4. Start the serverIn the Developer tab, switch the server on. Lokal looks for it on port 1234.
  5. Using WSL? Let it reach WindowsTurn on "Serve on Local Network" in the server's settings. LM Studio runs on Windows, and WSL reaches it over the network; Lokal finds the address by itself.
  6. Run lokalThat's it. To pin a server or a model, write them in ~/.config/lokal/config.

What it won't do

Lokal is defined as much by what it refuses.

  • Run anything that can change your machine without your yes. Which commands count as read-only is Lokal's own list, never the model's call.
  • Change a file without showing you the diff first, every time.
  • Take a key you pressed before the question as its answer.
  • Send anything anywhere, except one update check a day, which updates = off turns off.
